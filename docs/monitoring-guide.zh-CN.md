# 如何阅读监控证据

[English](monitoring-guide.md) · [关键词操作](keyword-monitoring.zh-CN.md) · [测量方法](measurement-methodology.md)

## 第一次观测

1. 创建项目、连接所选模型服务商，并保存模型基线。
2. 打开“关键词持续侦测”，添加真实问题，如 `best analytics tools for startups`。可选填写品牌及明确的别名；系统不会猜测未配置的缩写。
3. 选择频率、标签和每个模型 1–10 次采样。先手动运行一次，再启动独立 scheduler worker；浏览器临时 Key 不能用于该 worker。
4. 在“历史”中检查原始回答、失败、匹配名称、推荐与来源出现次数、运行条件。支持按 UTC 日期和模型筛选，并导出相同筛选范围的 CSV 或 JSON。
5. 第二次观测后，先阅读 Diff 可比性提示，再判断变化。回到原文和来源核查；有引用不等于该来源导致了推荐。

## 如何理解结果

下表仅为说明示例，不是真实模型实验：

| 结果 | 含义 |
|---|---|
| 5 个成功样本中提及 3 次 | 配置的品牌或别名出现在三份回答中，本次观测比例为 60%。 |
| 4 个成功样本中提及 3 次，另有 1 次失败 | 失败不是未提及，应同时报告 3/4 和 1 次失败。 |
| 未配置品牌 | 原文、推荐和来源仍保存；配置品牌前，品牌提及比例没有业务意义。 |
| 没有可比较结果 | 条件变化，或对应样本缺失/失败；不能解释为可见度下降。 |
| 重试快照 | 包含从原运行保留的样本，不能算作一轮独立重复观测。 |

图表逐次展示观测，不提供加权分数，也不跨条件连接趋势线。请检查基线、问题、模型、联网配置和采样协议。重复采样也不保证未来可见度，不代表统计置信区间；API 回答不等于消费端 AI 产品的回答。

推荐标签来自模型结构化回答，不通过中英文触发词表猜测情绪。中文回答与配置的别名走同一证据流程。旧 Alpha 引擎的启发式情绪诉求，与当前产品的推荐测量是不同需求。

## 调用量与 CLI 重复采样

在工作台创建关键词监控后，使用其项目和监控 ID：

```sh
npx tsx src/cli.ts keyword-run --project PROJECT_ID --monitor MONITOR_ID --repeats 5 --dry-run
npx tsx src/cli.ts keyword-run --project PROJECT_ID --monitor MONITOR_ID --repeats 5
```

预估模式只读取保存的配置，输出“模型数 × 采样次数”、最大请求输出 token 数和未知金额；服务商重试或联网可能额外计费。第二条命令使用服务端密钥实际运行，保存新观测，并输出每个模型的品牌提及、推荐和来源出现次数。此次覆盖不会修改已保存的采样设置或频率。部分失败返回非零退出码，但证据仍保留。当前工作台使用 `schedule:worker`，`monitor-worker` 属于旧引擎。

## 排查与离线案例

- Worker 未运行或心跳过期：检查 `npm run schedule:worker`、数据目录和服务端密钥。先看失败记录，不要反复重跑全部模型。
- 某模型失败：从最新兼容记录中只重试该模型的失败样本。旧协议记录仍可读取，但应先创建新观测，不能用新识别规则混合重试旧样本。
- 暂无 API：阅读[真实研究归档](../examples/README.zh-CN.md)。可运行 `npm ci`、`npm test`、`npm run test:examples` 做不调用模型的安装检查。测试使用明确的模拟输入，不是研究结果，也不写入你的工作台。
- 需要原始数据：CSV 包含每个样本的回答、错误、条件和来源；JSON 保留筛选后的运行证据。导出不会增加密钥信息。
- 本版不增加 Webhook 告警、地区代理模拟、PDF 报告和标签聚合评分。它们的独立范围记录在[Issue 整理清单](issue-triage-v0.3.3.md)。
