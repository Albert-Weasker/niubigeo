# NiubiGEO v0.2.1

Released September 28, 2026 / 发布日期：2026 年 9 月 28 日。

## What's new / 新功能

- Click one of 16 platform logos to enter your API key, with the applicable endpoint prefilled. Cards identify provider keys versus OpenRouter keys.
- Mix OpenRouter, direct provider APIs and custom OpenAI-compatible models in one test. Discover models via `/models` or enter IDs manually.
- Keep endpoint/model identities, search settings, answers, citations and failures separate. Same-name models from different endpoints remain independent.
- Browse all current OpenRouter text models and filter by platform, API source and search capability.

点击 16 个平台 Logo 即可输入 Key；支持自动读取或手填型号，在同一次测试中混选 OpenRouter、厂商直连与自定义接口，按来源和型号分别保存结果。模型目录提供主流平台、来源与联网能力筛选。

[English connection guide](../model-connections.md) · [中文使用指南](../model-connections.zh-CN.md)

## Download and run / 下载与运行

Download `niubigeo-v0.2.1-source.zip` or `niubigeo-v0.2.1-source.tar.gz` from this release. Verify the archive against `SHA256SUMS`. The archives contain source, documentation and assets; Node.js 22+ and `npm ci` are required. They contain no keys, user data or installed dependencies.

下载本版本的 ZIP 或 TAR.GZ 源码包，使用 `SHA256SUMS` 校验。解压后安装依赖并启动：

```bash
cd niubigeo-v0.2.1
npm ci
npm run server
```

Open <http://localhost:8787>, create a project and click a platform logo to enter your key.

Docker (Linux amd64 / arm64):

```bash
docker pull ghcr.io/albert-weasker/niubigeo:v0.2.1
docker run -d --name niubigeo \
  -p 127.0.0.1:8787:8787 \
  -v niubigeo-data:/app/data/product-v2 \
  ghcr.io/albert-weasker/niubigeo:v0.2.1
```

The release workflow builds and checks both architectures before publishing `v0.2.1` and updating `latest`. Back up existing data before upgrading; see the [Docker guide](../deployment/docker.md) and [upgrade guide](../upgrade.md).

## Boundaries / 使用边界

- Browser keys are session-only; reconnect after refreshing. Temporary custom connections are not available to the separate scheduler worker.
- Custom endpoints use Chat Completions; structured GEO analysis additionally requires JSON Schema support. Custom native search is unverified and disabled.
- Platform cards labeled OpenRouter require an OpenRouter key. Consumer products without corresponding API models are not substituted with unrelated models.
- This release retains the existing [known issues](../known-issues.md). Automated fixtures do not establish real-provider compatibility for every model. No new paid inference was used for release validation.

浏览器 Key 仅保留在当前会话，刷新后需要重新连接，不能交给独立定时 Worker 使用。自定义接口的结构化分析要求支持 JSON Schema；其原生联网能力尚未验证，不开放联网开关。自动化测试不代表已逐个实测所有厂商型号。
