# NiubiGEO v0.3.0

Released October 8, 2026 / 发布日期：2026 年 10 月 8 日。

v0.3.0 adds an independent Keyword Monitoring module to the existing workbench. It keeps keyword monitoring separate from domain recognition while reusing the saved project models and scheduler infrastructure.

## What's new / 新功能

- Add one keyword or import a newline-separated batch.
- Start from AI Coding, SaaS / Product, GEO and brand-comparison templates.
- Classify monitoring prompts as Discovery, Alternative, Comparison, Brand or Use case.
- Run monitors hourly, daily or weekly.
- Optionally configure a monitored brand and aliases, including `牛逼GEO` and `NiubiGEO`.
- Keep each run's answer, model, mentions, positions and citations in independent history.
- Compare the previous and latest snapshots in Diff View, including added or removed recommendations, mention-position changes and added or removed source links.
- Add bilingual Keyword Monitoring documentation.

v0.3.0 does not include a separate competitor detection dashboard. That work remains outside this release.

## Download and run / 下载与运行

Download `niubigeo-v0.3.0-source.zip` or `niubigeo-v0.3.0-source.tar.gz` from this release. Verify the archive against `SHA256SUMS`. The archives contain source, documentation and assets; Node.js 22+ and `npm ci` are required. They contain no keys, user data or installed dependencies.

```bash
git clone --branch v0.3.0 --depth 1 https://github.com/Albert-Weasker/niubigeo.git
cd niubigeo
npm ci
npm run server
```

Open <http://localhost:8787> and choose **Keyword Monitoring NEW / BETA** in the workbench navigation. Scheduled runs require the monitoring worker and server-side model keys; see the [Docker deployment guide](../deployment/docker.md).

Docker (Linux amd64 / arm64):

```bash
docker pull ghcr.io/albert-weasker/niubigeo:v0.3.0
docker run -d --name niubigeo \
  -p 127.0.0.1:8787:8787 \
  -v niubigeo-data:/app/data/product-v2 \
  ghcr.io/albert-weasker/niubigeo:v0.3.0
```

## Boundaries / 使用边界

- Keyword Monitoring remains labeled **NEW / BETA** because its APIs and metrics may change.
- Browser keys are session-only. The separate scheduler worker requires server-side model keys.
- Runs use the models saved in the workbench and incur the corresponding model/search costs.
- A single answer is an observation, not a universal ranking. Diff View compares stored runs; it does not create a GEO score.
- The existing known issues and evidence limitations remain applicable.

关键词持续侦测仍标记为 **NEW / BETA**，接口和指标可能调整。浏览器 Key 仅保留在当前会话；定时 Worker 需要服务器侧模型 Key。运行会使用工作台中保存的模型并产生相应模型/搜索费用。单次回答只是一次观察，Diff View 只比较已保存的运行，不生成新的 GEO 分数。
