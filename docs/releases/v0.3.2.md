# NiubiGEO v0.3.2 — Security update / 安全更新

Fixes #242: website evidence collection now rejects private, loopback, link-local, cloud metadata and reserved destinations. Every redirect is validated and each connection is pinned to validated DNS answers. Homepage, linked-page, sitemap and domain-profiling requests share this protection. Invalid local destinations submitted to `/audit-plan` return 400. The local model-provider override does not disable website-fetch protections.

修复 #242：网站证据抓取拒绝内网、本机、链路本地、云元数据及保留地址；逐跳检查重定向，并固定连接到已验证的 DNS 地址。首页、站内页面、站点地图及域名分析统一防护。`/audit-plan` 对非法本地目标返回 400；本地模型服务配置不能关闭网站抓取防护。

## Docker upgrade / 镜像升级

After both architectures pass container acceptance, all existing Docker tags—including historical version and `sha-` tags—are repointed to the same v0.3.2 security image at the owner's explicit request. They become compatibility aliases, not reproductions of their original source commits. The package and OCI labels identify the actual v0.3.2 source. Git tags remain unchanged. The workflow archives previous and new digests for every alias.

双架构容器验收通过后，按项目所有者要求，所有现有 Docker 标签（含历史版本及旧 `sha-` 标签）统一指向 v0.3.2 安全镜像。旧标签成为兼容别名，不再代表原提交构建；镜像内部版本及 OCI 标签记录真实源码版本。Git 历史标签不变，更新前后 Digest 保存在工作流附件。

```bash
docker compose --profile monitoring pull
docker compose --profile monitoring up -d --no-build
```

Preserve existing data volumes. Old downloaded images, running containers and deployments pinned to an old digest cannot be updated remotely. Change digest-pinned deployments to `ghcr.io/albert-weasker/niubigeo:v0.3.2` (or its verified digest), pull and recreate. Older v0.1/v0.2 users should follow the storage migration instructions before upgrading.

保留数据卷。已下载镜像、正在运行的容器和固定旧 Digest 的部署无法远程更新；需要修改镜像引用、重新拉取并重建。v0.1/v0.2 用户应先按部署文档备份及迁移存储，再升级。
